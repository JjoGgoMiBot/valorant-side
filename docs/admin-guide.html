01 / 경기 준비와 진행

내전 관리자 안내장

시작 전 5분

  • 참가자 10명과 A·B팀장, 진행자를 먼저 정해요. 팀 편성은 운영진이 별도로 해요.
  • 경기 방식(Bo1·Bo3·Bo5), 맵 풀, 밴 제한시간을 양 팀장과 합의해요.
  • 사이트는 맵·첫 진영을 정하는 도구예요. 게임 로비 생성과 승패 기록은 직접 해요.

1. 방 만들기

  • 진행자는 보관 중인 호스트 링크로 접속해요. 일반 공개 주소는 관전용이에요.
  • 팀 이름 → 맵 밴픽 또는 맵 룰렛 → 경기 수 → 맵 풀을 정하고 방을 만들어요.
  • 밴픽 최소 맵 수: Bo1은 2개, Bo3는 5개, Bo5는 7개예요.
  • Bo3·Bo5를 할 때는 모드를 반드시 “맵 밴픽”으로 선택해요.

2. 링크 나눠 주기

  • 관리자 패널의 A팀장·B팀장 링크는 각 팀장에게 개인적으로 전달해요.
  • 팀원 채팅 링크는 해당 팀에만, 관전 링크는 공지 채널에 전달해요.
  • 다른 서버에서도 운영한다면 방 번호가 들어간 관전 링크를 공유해요.
  • 기본 주소의 “최신 방”은 공용 호스트를 따라가므로 서버별 전용 로비가 아니에요.

3. 가위바위보 → 밴픽 → 진영

  • 양 팀장이 자기 링크로 들어와 가위바위보를 해요. 이긴 팀이 밴픽의 A 시드예요.
  • Bo1: 번갈아 밴 → 마지막으로 남은 맵 → 해당 차례 팀이 첫 진영 선택.
  • Bo3: 양 팀 1회씩 밴 → 양 팀 1맵씩 픽(상대가 진영 선택) → 추가 밴 → 결정전.
  • Bo5: 양 팀 1회씩 밴 → 양 팀이 번갈아 총 4맵 픽(상대가 진영 선택) → 결정전.
  • 결정전의 첫 진영은 가위바위보 승자가 선택해요. 화면의 현재 차례를 따라가요.
  • 룰렛: 진 팀장이 맵을 돌리고 이긴 팀장이 첫 진영을 선택해요. 한 맵씩 진행해요.

4. 발로란트 로비에 반영

  • 확정된 맵 순서와 각 맵의 첫 공격·수비를 복사해 양 팀장에게 확인받아요.
  • 게임 로비의 맵·팀·첫 진영을 직접 맞추고 시작해요. 점수는 운영진이 기록해요.
  • Bo3는 2승, Bo5는 3승이면 종료해요. 남은 결정전 맵은 동률일 때만 플레이해요.

02 / 관리자 패널 빠른 참고

진행 중 문제 해결

상황별로 누르는 버튼

  • 밴·픽·진영을 잘못 선택: “한 단계 되돌리기”로 마지막 단계만 취소해요.
  • 팀장 부재·접속 문제: 상황을 공지한 뒤 “A팀/B팀에 선택권 주기”를 사용해요.
  • 현재 준비를 처음부터: “이번 게임 다시 시작”. 이전 선택은 다시 진행해요.
  • 현재 준비를 마치고 새 게임 준비: “다음 게임”. 실제 승패를 자동 기록하지 않아요.
  • 경기 방식·맵 풀 변경: “규칙 · 맵 풀 바꾸기” → “설정 적용”. 처음부터 다시 시작돼요.
  • 팀장 링크 유출·교체: “팀장 링크 재발급” 후 새 링크를 두 팀장에게 다시 전달해요.
  • 도배·방해: 전체 채팅 잠금 또는 반응 이모지 끄기. 팀 채팅은 유지돼요.
  • 완전히 새 진행: “새 방 만들기”. 보관할 결과를 먼저 복사해요.

접속이 안 되거나 차례가 멈출 때

  • 모두 같은 방 번호인지, 본인 역할이 팀장인지 먼저 확인해요.
  • 관리자도 즉시 초기화하지 말고 화면과 현재 결과를 먼저 저장해요.
  • 팀장은 최신 링크로 다시 들어와요. 계속 안 되면 진행자가 대신 진행해요.
  • 연결이 끊기면 사이트의 재연결을 확인해요. 공용 실시간 중계 서버 장애가 있을 수 있어요.
  • 복구가 안 되면 공지 후 새 방을 만들거나 합의한 수동 밴픽으로 진행해요.

링크 보관 원칙

  • 호스트 링크와 관리자 링크는 운영진만 보관해요. 링크 소지가 권한이에요.
  • 팀장 링크와 팀원 채팅 링크도 공개 공지·스크린샷·GitHub에 올리지 않아요.
  • 사이트 주소가 바뀌면 브라우저의 저장된 권한이 옮겨오지 않을 수 있어요.
  • 새 주소에서 기존 호스트 링크의 경로만 바꿔 접속하고, 새 방 링크를 다시 나눠 줘요.
  • 일반 공개 주소만 새 주소로 바꾼다고 관리자 권한이 생기지는 않아요.

운영진이 사전에 합의할 항목

  • 지각·연결 종료 시 대기 시간, 일시정지 횟수와 길이, 재경기 기준을 정해요.
  • 맵·진영 오류는 경기 시작 전에 양 팀장이 확인해요.
  • 규칙 변경·되돌리기·강제 진행은 사유와 양 팀 확인 내용을 운영 기록에 남겨요.
  • 첫 외부 서버 운영은 소규모로 리허설하고 본 경기를 진행해요.
